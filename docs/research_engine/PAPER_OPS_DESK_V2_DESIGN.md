# 纸面操作台 V2（Paper Ops Desk）— Design

> 日期 2026-09-07。触发：用户准备操作模拟盘，提出一组"每天怎么用"的问题。
> 本文件先回答问题（产品视角），再给出实现设计。**不改 ML1，不改 V26.8 外壳，不发单。**

---

## 0. 先把结论摆出来（用户的问题逐条）

| 问题 | 答案 | 依据 |
|---|---|---|
| 明天要不要看它指示我卖出/加仓/加新股？ | **不会有**。策略每 21 个交易日只操作一次：信号日收盘出名单 → 次日开盘买 → 持有 20 个交易日 → 卖出日开盘全部卖 → 当晚出新名单。中间每一天系统的回答都是"今天无需操作"。没有加仓、没有做 T、没有止损。 | V26.8 合同；V34 出场规则诊断 13 条全部不比现状好；V33 短线可预测但不可交易 |
| 卖出在哪里显示？ | 英雄卡「今天要做什么」。到卖出日显示「今天开盘：卖出全部 N 只」并列名单；平时显示「持有第 k/20 天 · 下一次操作 X 日」。 | 现有 `today_action` 扩成完整 `plan` |
| 今天算的名单，明天再算会不会换一批？ | **不会**。名单只在信号日生成；非信号日运行只补数据、不出新名单。以前 `--force-score` 在非信号日强行出过一份（09-04），V2 把它标成「非操作日预览」，不再当作当前名单。 | `chain_signal_indices` |
| 看不到历史推荐 | V2 加「历史每一期」时间线：每期信号日/买入日/卖出日/只数/收益/vs 等权/状态，可展开当期名单。 | `LEDGER_TOP20.periods` + `SHORTLIST_SHADOW_*.json` |
| 我买卖后要不要标记？系统按我的状态给指导？ | **要**。V2 加成交日志（买/卖/入金/出金）。有日志后，「我的资金」「我的持仓」「资金检查」全部按你的真实成交算；没日志就退回模型影子账本。 | `live/paper/JOURNAL.json` |
| 出新名单前先看余额？ | **是**。买入日的名单手数按「你的可用现金 − ¥200 预留」重算（同一套 V26.8 算术）；现金不够就自然少买几只/少几手；上期还没卖干净会红字提醒「先卖后买」。不会建议"卖别的换这只"或做 T。 | `preview_lots` |
| 每天要手动更新数据吗？ | 需要点一下（或者你以后设 Windows 计划任务）。V2 在页面放「更新数据」按钮，后台跑 `daily.py`，有进度、有日志。**不更新也不会给错名单**：名单只依赖信号日收盘，所以只要信号日当晚（或次日开盘前）更新过就够；平时不更新只是持仓市值不刷新。 | run manager |
| 几点更新？几点看名单？ | 收盘后 **18:30 以后**更新（BaoStock 日线一般 17:30–18:00 齐）；忘了就次日 **08:30 前**补。操作日 09:15–09:25 集合竞价或 09:30 开盘按名单下单。 | BaoStock 更新时点 |
| 更新到一半断了/报错/重复点？ | 管线每步幂等：日线按缺失交易日补、融资按日文件、户数按文件龄。中断后再点一次会从缺的地方继续；重复点无害（有锁：正在跑时按钮灰掉，第二次点只是看进度）。上次失败/中断会在状态栏红字提示，并给日志。 | `update_bars` idempotent；锁文件 |
| 第二天会补前面缺的数据吗？ | 会。`daily.py` 补 (冻结末日, 今天] 之间所有缺的交易日。 | `panel.refresh_all` |
| 新闻、财报等要更新吗？ | ML1 只用价格 + 融资 + 户数 + 指数成分 + 年报（年更），全部在 `daily.py` 里自动增量。新闻不用（不是特征）。季报/预告/增减持/质押是 ML7 影子的输入，也已并进同一次运行。 | V25/V38-S3 |
| 每次计算要用付费数据吗？ | **不用**。BaoStock、东财数据中心、中登（经东财）全部免费。Databento 只花在期货研究上，与 A 股每日运行无关。 | 数据源清单 |

**明确不做的（用户提到但本设计拒绝）**：加仓、做 T、不好的票提前卖、用当天行情改名单。原因不是懒，是这些在研究期都测过且更差（V33/V34），而且没有事前规则的临场决定就是在用运气改合同。

## 1. 每日流程（拓扑）

```
                 ┌──────────── 平时（20 个交易日）────────────┐
信号日 D 收盘 ── 18:30 更新数据 ── 出名单 ─▶ D+1 开盘买入 ─▶ 登记成交 ─▶ … 持有 … ─▶ D+21 开盘卖出全部 ─▶ 登记成交
                                                                                                  │
                                                                                    D+21 当晚 18:30 更新数据 = 下一个信号日 ──▶ D+22 开盘买入
```

- 卖出与买入不在同一天：D+21 早卖，D+21 晚出名单，D+22 早买。卖出的现金 A 股当日可用于买入，次日可提。
- 每月第一个信号日：先入金 ¥2,000 再算名单（V26.7 约束）。页面会提醒「本月定投未登记」。
- 卖出遇到跌停/停牌：该票状态改成「顺延」，次日再卖，最多 10 日（V26.4）。其余票正常。

## 2. 页面状态机（英雄卡）

| 条件（以真实日历为准） | 英雄卡 | 附带 |
|---|---|---|
| 数据截至 < 上一个已完成交易日 | **先更新数据**（红） | 落后几日、更新按钮 |
| 今天 = 卖出日 | **今天开盘：卖出全部** | 卖出清单（实际持仓优先）、登记成交 |
| 今天 = 信号日 且 已出名单 | **今晚名单已出：明早开盘买入** | 名单 + 资金检查 |
| 今天 = 信号日 且 未出名单 | **今晚 18:30 后更新数据出名单** | |
| 今天 = 买入日 | **今天开盘：买入名单** | 名单（按你的现金重算手数）、资金检查、未卖尽提醒、登记成交 |
| 其他，有持仓 | **今天无需操作** | 持有第 k/20 天、下一次操作日、倒计时 |
| 其他，我的账户空仓（期中） | **你还没有持仓 · 等 X 日买入** | 合同不中途进场；提示先入金；下一信号日/买入日 |

### 2.1 两个账户，一个开关（2026-09-07 11:50 用户反馈后修正）

用户反馈：「我模拟账户还没买呢，为啥数据和推荐不是根据目前情况来的？」「推了 10 只我买了 3 只，第二天别按我全卖了算」「历史每一期切换账户也得切」。原 V2 只有持仓表有 tab，英雄卡 / 资金 / 历史都来自模型账本 → 误导。修正：

- 顶栏一个全局开关 **「我的模拟账户」/「模型影子账本」**（记在 `localStorage`），整页跟着切：英雄卡、横幅、操作清单、三个数字、持仓、每一期。
- 后端 `ops()` 同时给 `plans.actual` / `plans.model`、`history_actual` / `history_model`，两条链**互不影响**：
  - 我的账户 = 只按成交日志。没登记 = 空仓（不再回退到模型账本）。买 3/10 只 → 持仓 3 只、卖出日只列 3 只、`warnings` 写「你只买了 3/10 只」、每一期按 3 只算投入/收回/盈亏。期中空仓 → `NO_POSITION/WAIT`，明示不中途进场，等下一买入日。
  - 模型账本 = 官方 V26.8（全买、¥20,000、月定投）只读；不受用户买了几只影响；只有它显示「非操作日预览」名单。
- `history_actual` 状态：`OPEN`（还有未卖）/ `CLOSED` / `NOT_TRADED`（那期没买）/ `PENDING_ENTRY`（信号已出、买入日未到）。
- 买入名单每行「已买，登记」只在我的账户下显示；「一键按计划登记」明示只买几只请逐只登记。

## 3. 数据与接口

新增文件（都在 `data/market/cn_a_share/live/`，均不进冻结目录）：

- `paper/JOURNAL.json`：`{account:{base_cash}, events:[{id, ts, type: BUY|SELL|DEPOSIT|WITHDRAW|NOTE, date, symbol, lots, price, fee, note}]}`。持仓、现金都从事件推导（不存派生量）。
- `runs/CURRENT.json`：运行锁 `{pid, started_at, log, args}`；`runs/RUN_{ts}.log`：`daily.py` 输出。

新增接口（见 SPEC §29.5–§29.8）：`GET /api/v1/paper/ops`、`POST /api/v1/paper/update`、`GET /api/v1/paper/update/status`、`GET/POST/DELETE /api/v1/paper/journal`。

## 4. 不变量

- `daily.py` 的参数不由页面改：官方影子账本仍是 ¥20,000 + 月 ¥2,000 的 V26.8；用户真实资金的手数只在页面层用同一算术重算。
- 页面永不 `order_send`。
- 没有任何出场规则、仓位择时、名单微调进入 `daily.py`。

## 5. 五阶段

Phase 1 Design（本文件）→ Phase 2 Implement（`paper_ops.py` + `paper.html`）→ Phase 3 Smoke（接口 + 浏览器）→ Phase 4 Stability（跟 V29 一起到 09-29 第一次真实卖出日）→ Phase 5 Freeze。
