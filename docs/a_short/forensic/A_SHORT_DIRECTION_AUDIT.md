# A_SHORT_DIRECTION_AUDIT.md

> §6：当前 A-Short 更接近 A/B/C/D？为什么？（基于代码事实，不看愿景）

选项：
```
A: 简单动量策略
B: 量化选股系统
C: 短线热点交易系统
D: AI 辅助投资研究平台
```

---

## 判定
| 视角 | 判定 | 理由 |
|------|------|------|
| **当前实现（代码）** | **A（简单动量策略）** | 唯一打分 = 20D 动量；ALL universe 无质量过滤；无因子/ML/信息层/热点/龙头/资金流/LLM。就是「全市场 20 日动量 Top-K」的离线回测。 |
| **工程成熟度（引擎）** | 略触及 **B** 的边 | 有正规撮合/T+1/成本/账户/评估/多重性登记的**引擎**，比"玩具动量"严谨；但**缺多因子/选股逻辑**，够不上 B。 |
| **架构文档意图** | 朝 **D** 设计 | docs/a_short 大量设计 LLM 决策支持、信息层融合、GUI、通知、scheduler、纸面操作台——是"AI 辅助研究平台"蓝图。 |
| **Owner 需求本质** | **C ∩ D** | 「短线/超短线 + 热点/龙头/涨停/连板/龙虎榜/资金流/板块轮动 + 政策催化 + 每日推荐 + GUI/通知/模拟盘」= **短线热点交易系统（C）**，并以 **AI 研究平台（D）** 为承载。 |

## 结论
> **当前 = A。文档 = D 蓝图。需求 = C（融合 D）。**
> 实现停在「简单动量策略」，而目标是「短线热点交易系统 + AI 研究平台」——**中间隔着数据（分钟/龙虎榜/资金流/新闻政策）、信息层接入、热点/龙头/板块衍生、ML/LLM 融合、GUI/通知/scheduler/live 账本**等**数量级工作量**，且被 D1 冻结字节在 Cloud 不可用**硬阻塞**。

## 是否"走偏"？
- **没有走错方向，但严重"未到位"且有"β 错觉"风险。**
  - 20D 动量 + 无质量过滤 → 天然选小盘/低价/垃圾股（见 `CURRENT_UNIVERSE_REPORT.md`）。若未来看到"高收益"，极可能是**小盘 β 而非短线 alpha**（ML1 系列反复教训：大半是 β）。
  - "短线"意图 vs "20 日动量"信号 = **horizon 方向不符**（信号是中周期，持有期才是短线）。
- **正确的部分**：引擎/成本/执行/PIT/纪律（预注册、多重性、DATA_BLOCKED 诚实、不美化）是扎实地基，值得保留。

## 一句话给 Owner
A-Short 现在是"一个严谨但空的短线**引擎** + 一个 20 日动量占位信号"，不是短线热点系统。要成为 C/D，需要先解冻数据、再逐层接入信息与热点/龙头逻辑、再上 ML/LLM 与 GUI/通知——每一步都是新合同、新工程，不能靠调参。
